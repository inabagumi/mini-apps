# あなたのオタクタイプ診断 by あにまーれ

[あなたのオタクタイプ診断 by あにまーれ (あにまーれ診断)](https://shindan.animare.cafe/) は有閑喫茶あにまーれや有閑喫茶あにまーれに所属するメンバーを題材とした非公式のウェブサービスです。[あなたのオタクタイプ診断 by IRIAM](https://shindan.iriam.com/) をオリジナルとして、デザインやレイアウトの転用をしていますが素材の流用は一切行っていません。

## 開発

### シード

`prisma/seed/data.ts` のシードデータは開発とテストのためのもので、本番環境のデータとは関係がありません。本番環境のデータと区別できるように、質問、選択肢、診断結果、タレント、リリースには「テスト質問1」や「テスト結果A」のようなテスト用の値を使用しています。シードデータを本番環境のデータベースへ投入するデータとして扱わないでください。

`prisma/seed/data.ts` のデータを `pnpm exec prisma db seed` でデータベースに登録します。シードは1つのトランザクションで実行され、失敗した場合は何も登録せずに終了コード1で終了します。シードデータにIDやslugの重複、存在しないタレントへの参照がある場合は、トランザクションを開始する前に失敗し、データベースを変更しません。

診断結果のslugは公開URL (`/s/[slug]`) と結果画像 (`public/images/results/[slug].png`) に対応します。結果画像は本番環境の診断結果のためのもので、シードデータの診断結果には結果画像がありません (結果ページのOpen Graph画像が表示されません)。テストでは、シードデータの診断結果が結果画像と同じslugを使用していないことを確認します。

シードは冪等で、何度実行しても同じレコードを更新します。質問、選択肢、タレントは固定のIDで、診断結果とリリースはslugで識別します。シードデータにないレコードは変更や削除をしないため、シードデータから項目を削除してもデータベースからは削除されません。シードデータと同じIDやslugを持つレコードは上書きされるため、本番環境のデータベースでは実行しないでください。

### 診断結果の決定

選択肢ごとに診断結果へのスコア (0〜3点) を `answer_scores` テーブルに設定します。スコアが設定されていない組み合わせは0点として扱います。診断結果は全回答のスコアを結果ごとに合計し、次の順序で決定します (`lib/scoring.ts`)。

1. 合計スコアが最も高い結果
2. 同点の場合は3点を獲得した回答数が最も多い結果
3. それでも同点なら `slug` の昇順 (UTF-16のコード単位順) で最初の結果

乱数は使用しないため、同じ回答の組み合わせからは常に同じ結果になります。シードデータのスコアについては、テストですべての回答の組み合わせを列挙し、すべての診断結果に到達でき、各結果が選ばれる割合が均等な場合の半分以上2倍以下であることを確認します。

シードは、シードデータにある選択肢と診断結果の組み合わせのスコアをシードデータの内容に置き換えます。シードデータから削除したスコアはデータベースからも削除されます (0点になります)。

### テスト

シードのテストはPostgreSQLを使用します。`TEST_DATABASE_URL` が設定されていない場合は省略されます (CIでは失敗します)。リポジトリーのルートで `docker compose up --detach --wait postgres` を実行してPostgreSQLを起動し、次のようにテストを実行してください。

```bash
TEST_DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/postgres pnpm test
```

テストは一時的なスキーマを作成してマイグレーションを適用し、終了時に削除します。
